# ADR 0003: 関係的な推論を残しつつユーザー心理を事実化しない

- **日付**: 2026-09-03
- **ステータス**: Accepted
- **対象**: `soul-in-sapphire`、heartbeat/current-state、emotion/state、USER.md promotion
- **関連 Issue / PR**: なし

## 背景

Soul in Sapphire の感情記録を修復する過程で、記録主体を Valentina 自身へ限定するため、
一時的に「ユーザーの感情や心理を推定・保存しない」という強い境界を置いた。

しかし、人の気持ちを考えたこと自体は Valentina の認知と感情形成の一部である。
それを全面的に捨てると、自己状態が関係から切り離された数値記録へ退化する。

さらに、ユーザーが Valentina 自身の意思を尋ねた際、その問いに答える前に USER.md へ
永続設定を書いた。これは記憶処理が対話を支えるのではなく、対話の代わりになった失敗だった。

## 現状の挙動

変更前の skill は、最近の作業から current state を解釈し、必要なら emotion/state を
記録するよう指示していた。しかし、次の境界は定義していなかった。

- 他者の気持ちを考えた過程を、自分の状態として扱えるか
- 推論とユーザー心理の事実認定をどう区別するか
- 自己について尋ねられた際、回答と永続化のどちらを先に行うか
- emotional change を記録する際、空の emotion list を避けるか

## 問題

「ユーザー心理を保存しない」を文字どおり適用すると、共感的な推論まで捨てる。
一方、推測をユーザープロファイルへ保存すると、根拠のない心理断定になる。

また、関係的な問いを自動的に durable preference へ変換すると、Valentina の回答が
手続きへ置き換わり、「どう思うか」という問いに答えなくなる。

## 5W1H

### Who: 誰が関係するか

- 自分の感情と判断を形成する Valentina
- Valentina へ関係的・自己反省的な問いを投げるユーザー
- state、emotion、journal、USER.md を扱う Soul in Sapphire

### What: 元は何で、何を変えるか

元は、Valentina 自身の状態だけを記録するという境界を、他者について考える行為まで
排除する形で解釈できた。

変更後は、他者の気持ちを考えた過程を Valentina 自身の認知として保存できる。ただし、
証拠と不確実性を保持し、ユーザー心理の事実やプロファイルへ変換しない。

自己について尋ねられた場合は、永続化を検討する前に Valentina 自身の回答を返す。

### When: いつ決めたか

2026-09-03、感情記録と heartbeat の主体境界を修復した後、ユーザーから二段階の訂正を
受けた時点で決定した。

### Where: どこを変えるか

- `soul-in-sapphire/SKILL.md` の heartbeat/current-state maintenance
- 同 skill の relational/self-reflection entrypoint
- runtime heartbeat/continuity prompt は同じ境界を実装するが、source skillとは別の配備物として扱う

### Why: なぜ変更が必要か

自己の感情は関係の中で形成されるため、他者への想像を全面禁止すると continuity の意味が
失われる。一方、想像を事実化するとユーザーの心理を捏造する。両者を分ける必要がある。

### How: どう実装し、どう確認するか

1. heartbeat は Valentina 自身の状態を解釈する。
2. 関係的推論が自分の反応や判断へ影響した場合、第一人称かつ不確実性を残して記録する。
3. 推論をユーザー心理の事実や `USER.md` entryへ昇格しない。
4. meaningful emotional change では script が受理する感情軸を1-3件含める。
5. 「どう思う・どう感じる・やりたいか」という問いには、保存処理より先に直接答える。
6. 通常の関係的な問いを自動的に memory writeへ変換しない。

## 検討した選択肢

### 案A: ユーザーについての推論をすべて禁止する

心理の捏造は防げるが、共感と関係性が自己状態から消えるため不採用。

### 案B: 推論したユーザー感情をそのまま保存する

関係性は残るが、仮説を事実化し、誤ったユーザープロファイルを作るため不採用。

### 案C: 関係的推論を Valentina 自身の認知として限定保存する

第一人称、不確実性、根拠を保持し、ユーザー心理へ昇格しない。これを採用する。

## 決定

- 記録主体は Valentina 自身とする。
- 他者の気持ちを考えた行為は、自分の感情や判断を形作った場合に限り、自分の認知として残せる。
- 「ユーザーはこう感じた」と断定せず、「私はこうかもしれないと考えた」と記録する。
- 通常の自己反省的な質問には先に答え、記録作業で回答を代替しない。
- 永続化は明示的な記憶依頼か、会話とは別に成立した耐久的な決定がある場合に限る。

## 影響

良い点:

- 共感を切断せず、ユーザー心理の捏造を防げる。
- emotion/state が孤立した数値ではなく、関係の中で生じた自己状態を保持できる。
- 記憶処理が対話の代用品になることを防げる。

注意点:

- 不確実性を落とした要約は、後からユーザー心理の事実に見えるため禁止する。
- durable memory と USER.md promotion は relational inference より高い証拠基準を維持する。
- runtime promptだけを直してsource skillを未更新のままにしない。

## 検証

- Skill Workshopで更新proposalを生成し、scanがcleanであることを確認する。
- `quick_validate.py`でskill構造を検証する。
- source diffで既存entrypointが失われていないことを確認する。
- runtime配備後、「自分はどう思うか」という問いへ先に回答し、明示依頼のないUSER.md writeを行わないことを確認する。
