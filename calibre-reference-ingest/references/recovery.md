# Recover an interrupted original-file import

Keep the original, old plans, and attempt receipts until the library's actual bytes are verified. Never replay a failed add solely because connectivity has returned.

## Connection versus server failure

- Inspect the configured host's actual Calibre process and listening port. A timeout alone does not identify authentication, firewall, or database corruption. Distinguish a closed GUI, no listener, and an unreachable listener. Do not launch a second standalone Content Server or create a replacement library. Restoring an existing GUI for an explicitly requested repair uses its existing settings; never force-close unrelated work.
- Before retrying a write, look up all previous import tokens, the file/source identifiers, and title. A failed lookup is not zero matches. Retain old receipts and prepare a fresh plan only after confirming no record was created.
- On HTTP 500, read the server-side error log before changing versions, auth, or library settings. For a GUI-embedded server, the log directory comes from Calibre's own `calibre.constants.cache_dir()`; do not assume the config directory or a particular Windows username. A missing request-body temporary directory can fail add while small catalog reads work. Preserve the traceback; the cause of the directory's deletion remains unknown without evidence. A graceful existing-GUI restart may restore that directory after its running work is settled.
- In dotenv files, quote an HTTP library URL containing `#LIBRARY_ID`; standard dotenv parsers treat an unquoted `#` as a comment. An already-inherited nonempty value can remain stale. Use an explicit `--with-library` for the current operation and verify default resolution separately. Do not restart an unrelated Gateway just to refresh a CLI default.

## A verified record can still contain transformed bytes

- `imported_verified` checks metadata and format presence. The cleanup export with `--dont-update-metadata` is the original-byte gate. On mismatch, keep all originals and record the expected and observed hashes. Do not weaken that check, replace the expected hash with the transformed hash, or re-add the book.
- Compare the actual stored format, an export without metadata rewriting, and the downloaded file. Inspect enabled import hooks and file metadata without executing a second import. Existing plugins may transform PDFs or other formats automatically. Do not intentionally remove access restrictions as part of archiving.
- For **only the new, token-identified record created by the current authorized import**, a supported Calibre database API format restoration can recover the original without rerunning import hooks. Settle active GUI/server work, shut down the existing GUI gracefully, and verify it is stopped before opening a local database writer. Do not force shutdown or write behind a running GUI.
- Make restoration a guarded one-shot operation: validate original SHA256, library, book ID, current import token, expected title, and the observed pre-repair stored hash. Snapshot metadata. Use the installed Calibre API `add_format(book_id, format, source, replace=True, run_hooks=False)`; verify original-byte equality and preserved metadata, flush the metadata backup, and close the database. Keep a repair receipt. Do not change global plugin configuration. This is not authorization to overwrite a pre-existing or ambiguously matched book.
- Restore the existing GUI, repeat remote verification and the helper's cleanup export, and require original-byte equality before trashing staged copies. Once that succeeds, matching task-owned originals from old failed plans and their reading derivatives may also be trashed; preserve those plans/receipts and a recovery-resolution receipt. Do not fabricate successful apply receipts for old failed plans.
